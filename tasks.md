# Implementation Plan

Design decisions referenced below (§n) are recorded in `ARCHITECTURE.md`.

Every task is executed test-first: its tests are written and failing before any production code, per *Test-Driven Development* in `CLAUDE.md`. The verification tasks in Phase 4 are additional system-level checks, not the primary testing.

## Phase 0: Test Foundation
- [x] Establish the test layout: unit tests in `#[cfg(test)] mod tests` beside the code, cross-component tests in `tests/`, test modules allowing `unwrap`/`expect` so the zero-panic lints stay strict in production code.
- [x] Introduce an injectable `Clock` so `system_time` can be driven explicitly in tests, including backwards jumps that exercise the monotonicity clamp (§1).
- [x] Introduce an injectable sequence source so `seq` ordering is deterministic under test (§1).
- [x] Introduce a storage abstraction able to inject torn writes and I/O errors, so WAL recovery is tested deterministically instead of by killing processes (§4).
- [x] Add `proptest` and set up the invariant suite in `tests/invariants.rs`, with the properties the Phase 0 foundation supports.
- [x] Carried and now closed — all three §1 invariants are properties in `tests/invariants.rs`. *Resolution at an arbitrary observation point was mutation-checked: ignoring the point makes it fail.*

## Phase 1: Data Model & Ingestion Engine
- [x] Define the Arrow schema model (`timestamp`, `metric_id` as `u64`, attributes as real typed payload columns) with evolution rules: nullable column added = accept, column missing = null, type change = reject. Reject client schemas supplying the reserved `system_time`/`seq` columns (§6, §10).
- [x] Build the multi-table catalogue mapping table name to its durable `TableSchema` — recorded in the catalogue log (§4) — and its per-table configuration, applying evolution on ingest (§1, §6). *Retention duration joins `TableConfig` with §8; surfacing rejections as Flight errors lands with `do_put`.*
- [x] Build the metric registry mapping name + label set to a `u64` id, idempotent on re-registration, durable before visible through a `RegistrationLog` seam (§10).
- [x] Back the registry's `RegistrationLog` with the never-reclaimed catalogue log and recover it on start, skipping a torn tail (§4, §10). *The startup sequence that replays it ahead of the data log lands with `do_put`; the ordering rule is recorded in §4.*
- [x] Implement the Flight registration action returning ids for a name and label set, so clients resolve once and cache (§10). *Batched, over `do_action`; the service skeleton answers UNIMPLEMENTED for everything not yet served.*
- [x] Implement the system-column stamper appending `system_time` and `seq` on ingest, with `system_time` clamped so it never decreases as `seq` grows (§1).
- [x] Implement lock-free concurrent versioned `MemTable`: `(metric_id, timestamp)` identifies a logical row, many versions coexist, nothing is overwritten (§1).
- [x] Implement unchanged-value suppression: discard an incoming version whose payload digest matches the current latest version of the same logical row, over a per-table ingest-time window with a hard entry cap that survives freezes and is measured from the last touch (§1, §6).
- [x] Implement partition routing: split each incoming `RecordBatch` by the configured interval at insert time, since one batch may span interval boundaries (§3, §11). *One memtable per partition (§2) sharing one suppression index per table (§1); a single-partition batch passes through uncopied.*
- [x] Implement freeze-and-swap so a flush never blocks ingestion: freeze the active `MemTable`, open a new one, hand the frozen one to the background writer (§2).
- [x] Build append-only WAL with group commit (shared fsync, configurable max delay), per-record CRC, segment rotation, and checkpoint records for segment reclamation (§4).
- [x] Implement WAL replay: apply segments in sequence order, truncate at the first torn record, never fail startup on a damaged tail (§4). *Corrected afterwards: the tear truncates its own segment, not the log. Stopping at the first one hid everything written after the following recovery — a window in the data log, permanent in the never-reclaimed catalogue log.*
- [x] Implement Arrow Flight `do_put` streaming endpoint ingesting `RecordBatch` payload directly: assign sequence numbers, resolve the target table from `FlightDescriptor::path`, acknowledge only after fsync (§4, §5). *Batch replay into memtables lands with it, closing the startup gap.*
- [x] Implement backpressure: acknowledgements produced lazily so gRPC flow control carries the pressure back, plus `RESOURCE_EXHAUSTED` past the hard `MemTable` memory cap (§7).

## Phase 2: Parquet Storage & Archiver
- [x] Implement Parquet writer with ZSTD compression and page-level statistics on every column, `system_time` included, so old observation points skip whole row groups (§1). *Refuses an unsorted batch rather than sorting it; declares its sort order in the footer.*
- [x] Implement the parameterised Hive-style partitioner for the `hour`/`day`/`month`/`year` intervals, taking the interval as an argument rather than a global (§11). *Pulled forward: partition routing in Phase 1 cannot derive a path without it.*
- [x] Persist the partition interval in the instance metadata at initialisation and validate it against the on-disk layout at startup, refusing to start on a mismatch (§11). *Also refuses when partitions exist but the metadata is gone, since the layout cannot then be inferred.*
- [x] Build the background flusher transferring frozen `MemTable`s to Parquet, triggered per partition by size cap or max age — whichever fires first — writing `part-<seq>.parquet` sorted by `(metric_id, timestamp, seq)` with all versions preserved (§1, §2, §3). *Checkpoints one below the lowest `seq` still in memory, never the file's own. Driven by a background scheduler; a failed flush keeps its rows so the §7 cap refuses ingestion rather than losing them.*
- [x] Build the background compactor merging and re-sorting a partition's files into `(metric_id, timestamp, seq)` order once file count or total size crosses a threshold, emitting files of a configurable target size with disjoint `(metric_id, timestamp)` ranges, never dropping a version (§1, §3, §11). *Driven from the server on its own, longer interval; entries it cannot read are skipped rather than merged away.*
- [x] Implement per-table retention configuration and a background reaper dropping whole partition directories once their interval is entirely past the cutoff, by event time (§8). *Unset retention keeps forever and is never even examined; a directory the layout would not have written is left alone rather than dated by guesswork.*
- [x] Reject ingestion of data already outside the retention window in `do_put` with an explicit Flight error (§8). *`FAILED_PRECONDITION`, on exactly the reaper's rule — a row behind the horizon but sharing a partition with live data is accepted, since that partition is kept and served.*

## Phase 3: High-Performance Query Engine & Arrow Flight Output
- [x] Build DataFusion execution pipeline combining `MemTable` memory state and `Parquet` disk storage. *Parquet is read through an adapter onto the archive's own `Storage`, so there is one view of the bytes and the in-memory double sits under the query path too. Frozen memtables are held until their file exists, or a flush would make rows vanish from answers.*
- [x] Implement as-of version resolution: filter `system_time <= observation point`, then take the highest `seq` per `(metric_id, timestamp)` as a streaming merge over the sorted files — not a full-sort window function (§1). *A test reads the physical plan and fails on a `SortExec`; repartitioning above the merge is turned off, since it discards the order and pays to rebuild it.*
- [x] Expose each table as an as-of-resolved view plus `<table>$history` carrying the raw versions with `system_time` and `seq` as ordinary columns (§1, §5). *The observation point bounds `$history` too: seeing versions written after the point one observes from would contradict the point.*
- [x] Implement predicate pushdown and column projection for Parquet readers, including partition pruning via the Hive-style layout and row-group skipping on `system_time` and `metric_id` (§11). *A partition outside a bounded `timestamp` predicate is never opened, read straight off the directory name. Projection is asserted in bytes scanned.*
- [x] Resolve label predicates against the registry into a `metric_id` set and push that down as a filter on `metric_id` (§10). *`hetida_label('plant','a')` is a marker an analyzer rule replaces with literals before optimisation; a label nothing carries becomes `false`, never `true`.*
- [x] Expose the registry as a queryable catalog table, so labels are reachable from SQL rather than only through the registration action (§10). *Two tables: `hetida_series` lists every series, `hetida_labels` one row per label — neither alone can answer both questions, since a series with no labels has no row in the second.*
- [x] Implement `get_flight_info` and `get_schema` so generic Flight clients can follow the standard `get_flight_info` → `do_get` flow, accepting the same `{sql, as_of}` payload in the descriptor `cmd` (§5). *The ticket is the request, so nothing has to survive between the two calls and a ticket does not expire.*
- [x] Implement Arrow Flight `do_get` endpoint: parse `{sql, as_of}` from the `Ticket`, run it through DataFusion and stream results directly to clients via Arrow IPC (§5). *Streamed as produced: the size of an answer is the client's choice, not the server's.*
- [x] Implement TLS termination and Flight `Handshake` issuing bearer tokens, validated by a `tonic` interceptor once per call — never per streamed message (§9). *Token bytes come from an injected source, so production draws OS entropy and tests are deterministic. Serving without TLS, or without credentials, has to be written down.*
- [x] Implement per-table read/write authorization against the table from `FlightDescriptor::path` (`do_put`) and from the parsed SQL (`do_get`), behind a pluggable credential store with a static-config backend for v1 (§9). *Read grants are checked against the tables the planned query touches, so a join or a view cannot reach round them. `get_schema` needs the same grant as the rows.*

## Phase 4: Benchmarks & High-Concurrency Stress Testing
- [x] Micro-benchmark ingestion components with `criterion`: `MemTable` insert, WAL append, Parquet write. *`benches/ingest.rs`, plus the whole `Archive::ingest` so a regression can be attributed to a component rather than guessed at. All linear in batch size.*
- [x] Build a dedicated load harness (not `criterion` — network jitter invalidates its statistics) and measure `do_put` throughput with 100 parallel Arrow Flight clients. *`examples/loadgen.rs`, reporting order statistics rather than a mean: 306 000 rows/s, p50 151 ms, p99 321 ms over 100 clients on loopback.*
- [x] Measure `do_get` query latency and network throughput under heavy write load via the same harness. *Readers start before the writers, so the figure is read latency under load and not on an idle server: p50 201 ms, p99 375 ms.*
- [x] Verify zero-copy behavior, and that flushed and compacted files stay sorted by `(metric_id, timestamp, seq)` with every version preserved. *Zero copy by pointer identity — nothing else distinguishes a share from a copy of equal values. Sort order is also a property over generated runs.*
- [x] Verify time travel: write a value, correct it, and confirm each observation point returns the version current at that point — before the first write, between the two, and after. Include corrections that land after their partition was flushed and compacted. *Both as an example and as a property over arbitrary runs with flushes at arbitrary points.*
- [x] Verify retransmission suppression: re-sending an identical batch creates no new version and leaves every observation point's answer unchanged. *Across a flush, and checked at an earlier observation point too — a version count alone would not catch a moved answer.*
- [x] Benchmark as-of query latency against version depth (1, 10, 100 versions per logical row) to confirm the streaming merge does not degrade into a full sort. *0.88 ms / 1.36 ms / 5.90 ms for 1 / 10 / 100 versions — sublinear in the rows read, so the merge holds.*
- [x] Verify crash recovery: kill mid-write, confirm startup succeeds, acked data survives, the registry is intact, and replay is deterministic. *An injected torn write rather than a killed process; determinism is asserted by describing two replays of one store and comparing them.*
- [x] Verify metric pruning: a query on a few metrics out of many reads only the matching row groups, measured by bytes scanned rather than wall time (§11). *24 kB of 185 kB, by id and by label alike. This is what found the label pushdown reading whole files while answering correctly.*
- [x] Benchmark the partition interval variants (`hour`/`day`/`month`/`year`) against the real workload — few metrics over weeks to months — reporting files opened, bytes scanned and latency, to settle the default empirically (§11). *Recorded in §11. Rules out `hour` and `day` decisively; does not separate `month` from `year` at a thirty-day span, and says so.*
- [x] Verify retention: expired partitions are dropped, live partitions stay untouched, expired-range ingestion is rejected. *All three in `tests/pipeline.rs`, end to end from ingest through flush to the reaper and back to a refused write.*
- [x] Verify authorization: unauthenticated calls are refused, and per-table grants are enforced on both `do_put` and `do_get`. *`tests/authorization.rs` against a real server, including grants over rows already in Parquet and a token expiring mid-session.*
